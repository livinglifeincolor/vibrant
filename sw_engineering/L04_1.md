## 주요 내용 및 키워드 정리

### 1. 소프트웨어 아키텍처의 정의 및 중요성

- **정의**: 소프트웨어 시스템이 어떻게 구성되어야 하는지 이해하고, 시스템의 전체적인 구조를 설계하는 과정입니다.
- **역할**: 요구사항 공학(Requirements Engineering)과 설계(Design) 사이의 핵심적인 연결 고리이며, 주요 구조적 컴포넌트와 그들 사이의 관계를 식별합니다.
- **명시적 아키텍처의 장점**:
  - **이해관계자 통신**: 시스템 이해관계자 간의 토론을 위한 중심점이 됩니다.
  - **시스템 분석**: 시스템이 성능, 보안 등 비기능적 요구사항(Non-functional requirements)을 충족하는지 분석할 수 있습니다.
  - **대규모 재사용**: 아키텍처 자체를 유사한 시스템 라인에 재사용할 수 있습니다.

### 2. 주요 아키텍처 패턴 (Architectural Patterns)

패턴은 검증된 설계 지식을 공유하고 재사용하는 수단입니다.

#### Model-View-Controller (MVC)

- **특징**: 시스템 데이터(Model), 데이터 표현(View), 사용자 상호작용(Controller)의 세 가지 논리적 컴포넌트로 분리합니다.
- **장점**: 데이터와 표현 방식이 독립적으로 변경될 수 있으며, 동일 데이터를 여러 방식으로 보여줄 수 있습니다.
- **사용**: 웹 기반 애플리케이션 등 데이터에 대한 다중 뷰와 상호작용이 필요할 때 사용됩니다.

#### Layered Architecture (계층 아키텍처)

- **특징**: 시스템을 계층(Abstract machines)으로 조직화하며, 각 계층은 상위 계층에 서비스를 제공합니다.
- **장점**: 인터페이스만 유지된다면 특정 계층 전체를 교체하기 용이하며 보안 수준별 관리가 가능합니다.
- **단점**: 계층 간의 명확한 분리가 어렵고, 여러 계층을 거치면서 성능 문제가 발생할 수 있습니다.

#### Repository Architecture (저장소 아키텍처)

- **특징**: 모든 데이터를 중앙 저장소에서 관리하며, 모든 서브시스템은 이 저장소를 통해서만 데이터를 교환합니다.
- **장점**: 컴포넌트 간 독립성이 보장되며, 데이터 일관성 관리가 용이합니다. (예: IDE)
- **단점**: 저장소가 단일 장애점(Single Point of Failure)이 될 수 있습니다.

#### Client-Server Architecture (클라이언트-서버 아키텍처)

- **특징**: 데이터와 처리가 네트워크상의 여러 서버와 이를 호출하는 클라이언트로 분산됩니다.
- **장점**: 서버가 네트워크에 분산될 수 있고 일반적인 기능을 공통 서비스로 제공할 수 있습니다.
- **단점**: 네트워크 성능에 의존적이며 DoS 공격이나 서버 장애에 취약합니다.

#### Pipe and Filter Architecture (파이프 및 필터 아키텍처)

- **특징**: 데이터 처리를 개별적인 변환 단계(Filter)로 구성하고, 데이터가 파이프를 통해 흐르도록 설계합니다.
- **사용**: 주로 UNIX 쉘이나 배치(Batch) 처리 시스템에 사용되며, 대화형 시스템에는 적합하지 않습니다.

### 3. 응용 아키텍처 (Application Architectures)

특정 비즈니스 유형에 공통적으로 적용되는 범용 아키텍처입니다.

- **Transaction Processing Systems (트랜잭션 처리 시스템)**: 사용자의 데이터베이스 정보 요청이나 업데이트 요청을 처리합니다. (예: 이커머스, 예약 시스템)
- **Language Processing Systems (언어 처리 시스템)**: 자연어나 인공 언어를 입력받아 다른 형태의 표현으로 생성합니다. (예: 컴파일러, 커맨드 인터프리터)
  - 컴파일러 아키텍처는 **Repository 모델**이나 **Pipe and Filter 모델**로도 구현될 수 있습니다.
- **Information Systems (정보 시스템)**: 일반적으로 계층 아키텍처로 구성되며, 사용자 인터페이스, 통신, 정보 검색, 데이터베이스 계층으로 나뉩니다. (예: Mentcare 시스템)

### 키워드 정리

- **Structural Components**: 아키텍처를 구성하는 주요 부품들
- **Architectural Model**: 시스템 구조를 묘사한 결과물
- **Non-functional Requirements**: 성능, 보안 등 시스템의 품질 속성
- **Separation of Concerns**: MVC와 같이 기능을 독립적으로 분리하는 원칙
- **Distributed System**: 여러 컴포넌트에 처리가 분산된 시스템
- **Single Point of Failure**: 저장소 모델 등에서 발생하는 중앙 집중형 구조의 위험 요소
- **Abstract Machine**: 계층 아키텍처에서 각 계층이 상위에 제공하는 추상화 단계
