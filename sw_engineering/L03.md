## 주요 내용 및 키워드 정리

### 1. 소프트웨어 개발 방법론 (Software Development Methodology)

소프트웨어 시스템을 개발하는 데 필요한 일련의 활동(프로세스)을 추상화하여 표현한 모델입니다.

#### **주요 개발 모델**

- **폭포수 모델 (Waterfall Model):** 명확한 단계 구분(명세, 설계, 구현, 테스팅, 유지보수)을 특징으로 하며, 요구사항이 잘 이해된 경우에 적합하나 변경 수용이 어렵습니다.
- **병렬적 개발 방법론 (Parallel Development):** 프로젝트를 서브프로젝트로 나누어 동시에 진행하여 개발 기간을 단축합니다.
- **프로토타이핑 (Prototyping):** \* **진화적(Evolutionary):** 프로토타입을 확장하여 최종 시스템으로 발전시킵니다.
  - **Throwaway:** 요구사항 이해를 목적으로 제작 후 폐기하며 이후 Waterfall 방식을 적용합니다.
- **점진적 개발 (Incremental Development):** 시스템을 증분(Increment) 단위로 나누어 우선순위가 높은 기능부터 순차적으로 개발 및 배포합니다.
- **Unified Process (UP):** 반복적이고 점진적인 객체 지향 방법론으로, Inception, Elaboration, Construction, Transition 단계로 구성됩니다.
- **애자일 개발 (Agile Development):** 문서화 오버헤드를 줄이고 반복적 개발과 고객 참여를 강조합니다.
  - **XP (Extreme Programming):** TDD(Test-driven Development), Pair Programming 등을 실천하는 대표적인 애자일 방법론입니다.

### 2. 요구사항 분석 (Requirement Analysis)

제안된 시스템이 **'무엇(What)'**을 수행해야 하는지를 정의하는 단계로, 전체 소프트웨어 오류 중 56%가 이 단계에서 발생할 만큼 중요도가 높습니다.

#### **요구사항의 분류**

- **기능적 요구사항 (Functional Requirements):** 시스템이 제공해야 하는 서비스, 입력에 대한 반응, 특정 상황에서의 동작 등 행위(Behavior)에 관한 명세입니다.
- **비기능적 요구사항 (Non-functional Requirements):** 성능, 신뢰성, 보안성, 가용성 등 시스템의 속성이나 제약사항(Constraint)에 관한 명세입니다.
- **도메인 요구사항 (Domain Requirements):** 해당 분야의 기본 상식이나 전문 지식에 기반한 요구사항입니다.

#### **요구사항 분석 프로세스 및 명세**

- **프로세스:** 정보 수집(Elicitation) → 정보 기록(Specification) → 검사(Validation: 일관성, 정확성, 완전성 확인) 순으로 진행됩니다.
- **명세 기법:** 자연어(Natural Language), 구조적 자연어(Structured NL), 그래픽 표기법(UML Use Case 등), 수학적 명세 등이 사용됩니다.

### 3. UML 및 Use Case 분석

UML(Unified Modeling Language)을 사용하여 시스템의 기능적 관점을 모델링합니다.

- **Use Case Diagram:** 시스템의 범위와 기능을 Actor(외부 에이전트의 역할)와 Use Case(행위의 집합) 간의 관계로 표현합니다.
- **관계 설정:**
  - **포함(<<include>>):** 여러 Use Case의 공통 행위를 내포할 때 사용합니다.
  - **확장(<<extend>>):** 특정 조건이나 확장점에서 추가적인 행위가 수행될 때 사용합니다.
- **상세 기술:** 선행조건, 기본 흐름(Basic Flow), 예외 흐름(Exception Flow) 등을 상세히 기술하여 개발자와 고객 간의 소통 오류를 최소화합니다.

| 분류            | 주요 키워드                                                                |
| :-------------- | :------------------------------------------------------------------------- |
| **방법론**      | Waterfall, Iterative, Incremental, Agile, XP, Unified Process, Prototyping |
| **요구사항**    | Functional/Non-functional, Specification, Validation, Constraint, Domain   |
| **모델링/도구** | UML, Use Case, Actor, Relationship(Include/Extend), TDD                    |
| **품질/관리**   | Consistency, Completeness, Communication Error, Test Plan, Acceptance Test |

소프트웨어 개발 프로세스의 초기 단계인 요구사항 분석의 정확성이 프로젝트 전체의 비용과 성공 여부에 직결됨을 강조하고 있습니다.
