인터페이스 관점의 상속
- 클라이언트에게 부모 클래스만 노출해서 내부의 복잡한 구조를 숨긴다. (서브 시스템 커뮤니케이션에 많이 이용됨)
- 내부의 재귀적 정의가 숨겨질 수 있다.

singleton pattern (creational)
- 생성자를 protected로 선언해서 외부에서 instance 생성하는 것을 방지.
- 내부에 static 인스턴스를 유지하고 이에 접근할 수 있도록 하는 self pointer 제공.
- instance 함수는 self pointer가 NULL이면 객체 생성, 아니면 이미 존재하는 instance 리턴.
- 클라이언트는 객체의 참조를 최대한 빨리 사용하고 버려야한다.
- 상속을 통해서 확장될 수 있다.
- 시스템 내부에 정의된 글로벌 네임의 수를 줄일 수 있다.
- 단순히 static 메서드를 쓰는 것보다 flexible하다.

prototype pattern (creational)
- 런타임 클래스 지정이 가능하다.
- 복잡한 계층 구조를 피할 수 있다.
- 조합의 개수가 적을 때 편리하게 사용할 수 있다.
- 클라이언트가 알아야할 concrete 클래스의 수를 줄일 수 있다.

creational: singleton pattern, prototype pattern
structural: facade pattern, adapter pattern, composite pattern
behavioral: template method pattern, observer pattern
