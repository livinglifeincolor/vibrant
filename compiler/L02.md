## 렉심(Lexeme)과 토큰(Token)의 정의

- **Lexeme (렉심)**: 토큰의 패턴과 일치하는 소스 프로그램 내의 실제 문자 시퀀스입니다. 렉심은 어휘 분석기(Scanner)에 의해 특정 토큰의 인스턴스로 식별됩니다.
- **Token (토큰)**: 토큰 이름(Token Name)과 선택적인 속성값(Attribute Value)으로 구성된 쌍입니다. 토큰 이름은 키워드나 식별자와 같은 추상적인 기호를 나타냅니다.

### 코드 분석 사례

코드 식 `x = a + b * 2`를 어휘 분석할 경우의 결과는 다음과 같습니다.

- **Lexemes (실제 문자열 집합)**: `{x, =, a, +, b, *, 2}`
- **Tokens (추상화된 토큰 쌍)**: `{ <id, 0>, <=>, <id, 1>, <+>, <id, 2>, <*>, <id, 3> }`
  - 여기서 `id` 뒤의 숫자(0, 1, 2, 3)는 각 식별자를 구분하기 위한 속성값을 의미합니다.

## 언어의 정의 ($L(X)$)

패턴 $X$에 의해 묘사되는 렉심(문자열)의 집합을 '$X$의 언어'라고 부르며, 이를 기호로 $L(X)$라 표기합니다.

### 언어 연산 (Set Operations)

#### 1. 합집합 (Union)

- **표기**: $L \cup M$
- **정의**: $L \cup M = \{s \mid s \in L \text{ or } s \in M\}$
- **설명**: 언어 $L$에 속하거나 언어 $M$에 속하는 모든 문자열의 집합입니다.

#### 2. 연결 (Concatenation)

- **표기**: $LM$
- **정의**: $LM = \{st \mid s \in L \text{ and } t \in M\}$
- **설명**: 언어 $L$에서 뽑은 문자열 $s$ 뒤에 언어 $M$에서 뽑은 문자열 $t$를 붙여서 만들 수 있는 모든 문자열의 집합입니다.

#### 3. 클레이니 스타 (Kleene Star / Closure)

- **표기**: $L^*$
- **정의**: $L^* = \bigcup_{0 \le i \le \infty} L^i$
- **설명**: 언어 $L$을 0회 이상 무한히 연결하여 만들 수 있는 모든 문자열의 집합입니다.
- **특징**: $L^0 = \{\epsilon\}$을 포함하므로, **빈 문자열($\epsilon$)이 항상 포함**됩니다. ($L^i$는 $L$을 $i$번 연결한 것을 의미합니다.)

#### 4. 양의 클레이니 스타 (Positive Kleene Star / Positive Closure)

- **표기**: $L^+$
- **정의**: $L^+ = \bigcup_{1 \le i \le \infty} L^i$
- **설명**: 언어 $L$을 1회 이상 무한히 연결하여 만들 수 있는 모든 문자열의 집합입니다.
- **특징**: 클레이니 스타($L^*$)와 달리 빈 문자열($\epsilon$)을 기본적으로 포함하지 않습니다(단, $L$ 자체가 $\epsilon$을 포함하는 경우는 예외).

#### 주요 용어 정리

- **$\epsilon$ (Epsilon)**: 아무 문단도 포함하지 않는 **빈 문자열**을 나타냅니다.
- **$L^i$**: 언어 $L$을 $i$번 반복해서 연결(Concatenation)한 결과입니다.

## 정규 표현식

### 1. 정규 표현식의 목적

- 정규 표현식은 어휘 분석에서 **패턴(Pattern)**을 기술하기 위해 사용됩니다.
- 특정 정규 표현식 $r$은 그것이 묘사하는 렉심(Lexeme)들의 집합인 $L(r)$을 정의합니다.
- 렉심은 **알파벳($\Sigma$)**이라고 불리는 유한한 문자 집합들로 구성됩니다.

### 2. 정규 표현식의 귀납적 정의 (Inductive Definition)

알파벳 $\Sigma$에 대한 정규 표현식은 다음과 같은 규칙에 의해 정의됩니다.

#### [기초 단계: Inductive Base]

- **R1 ($\epsilon$):** $\epsilon$은 빈 문자열 집합 $\{\epsilon\}$을 나타내는 정규 표현식입니다.
- **R2 ($a$):** 만약 $a$가 알파벳 집합 $\Sigma$에 속한다면, $a$는 단일 문자 집합 $\{a\}$를 나타내는 정규 표현식입니다. (자료에서는 이를 명확히 하기 위해 기호 아래에 밑줄을 그어 표기합니다.)

#### [귀납 단계: Inductive Step]

만약 $x$와 $y$가 각각 언어 $L(x)$와 $L(y)$를 나타내는 정규 표현식이라면, 다음도 정규 표현식입니다.

- **R4 (Alternation, 선택):** $x | y$는 두 언어의 합집합인 $L(x) \cup L(y)$를 나타냅니다.
- **R5 (Concatenation, 연결):** $xy$는 두 언어의 연결인 $L(x)L(y)$를 나타냅니다.
- **R6 (Repetition/Closure, 반복):** $x^*$는 $L(x)$의 클레이니 스타(Kleene star)인 $L(x)^*$를 나타냅니다.

### 3. 연산자 우선순위 (Precedence)

복합적인 정규 표현식을 해석할 때 혼동을 방지하기 위해 다음의 우선순위를 따릅니다.

1.  **Closure (반복, $*$)**: 가장 높은 우선순위를 가집니다.
2.  **Concatenation (연결)**: 중간 우선순위를 가집니다.
3.  **Alternation (선택, $|$)**: 가장 낮은 우선순위를 가집니다.

## 유한 오토마타(Finite Automata, FA)

### **유한 오토마타의 구성 요소 (5-tuple)**

유한 오토마타는 수학적으로 다음 다섯 가지 요소의 집합으로 정의됩니다.

- **$\Sigma$ (Alphabet):** 해당 오토마타가 처리할 수 있는 입력 문자들의 유한 집합입니다.
- **$S$ (States):** 오토마타가 가질 수 있는 모든 상태들의 유한 집합입니다.
- **$\delta$ (Transition function):** 현재 상태에서 특정 입력 기호를 만났을 때 다음 상태로 이동하는 규칙을 정의하는 전이 함수입니다.
- **$I$ (Initial state):** 오토마타가 시작되는 지점인 시작 상태입니다.
- **$F$ (Final or Accepting states):** 입력 문자열이 성공적으로 인식되었음을 나타내는 종료(수락) 상태들의 집합입니다.

제시된 자료의 29페이지부터 32페이지는 **비결정적 유한 오토마타(NFA)**와 **결정적 유한 오토마타(DFA)**의 정의, 차이점 및 관계를 중점적으로 다루고 있습니다. 주요 내용을 기술적인 관점에서 정리해 드립니다.

### **비결정적 유한 오토마타 (NFA)**

#### **개념 및 특징**

- **다중 선택지:** 특정 상태에서 동일한 입력 기호에 대해 이동할 수 있는 다음 상태가 여러 개 존재할 수 있습니다.
- **$\epsilon$-전이 (Epsilon Transition):** 입력 기호를 소비하지 않고도 상태를 전이할 수 있습니다.
- **수용 조건:** 문자열 $x$에 대해 시작 상태 $s_0$에서 수용 상태(Final State)에 도달할 수 있는 경로가 **단 하나라도 존재**하면 해당 문자열을 수용합니다.

#### **동작 방식 (Simulation)**

- NFA를 실행할 때 매 단계에서 올바른 전이를 "추측(Guess)"한다고 가정합니다.
- 잘못된 추측으로 인해 유효한 문자열을 거부하는 문제가 발생할 수 있으므로, 가능한 모든 경로를 동시에 탐색하는 방식으로 시뮬레이션합니다.

### **결정적 유한 오토마타 (DFA)**

#### **DFA의 제약 조건**

DFA는 NFA의 특수한 형태로, 다음의 엄격한 규칙을 따릅니다.

- **$\epsilon$-전이 금지:** 입력 기호 없이 상태를 이동할 수 없습니다.
- **단일 전이:** 각 상태 $s$와 입력 기호 $a$에 대해, $s$에서 나가는 간선 중 라벨이 $a$인 것은 최대 하나만 존재해야 합니다. (즉, 전이 함수 $\delta(s, a)$가 단일 값을 반환함)

### **NFA와 DFA의 관계**

#### **비교 및 변환**

- **DFA $\subset$ NFA:** 모든 DFA는 본질적으로 NFA이기도 합니다.
- **등가성:** 모든 NFA는 그와 동일한 언어를 수용하는 DFA로 변환될 수 있습니다 (Subset Construction 알고리즘 사용).
- **효율성 대 복잡도:**
  - NFA를 DFA로 변환할 때 상태의 수가 지수적으로 증가(Exponential blowup)할 위험이 있습니다.
  - 하지만 변환된 DFA는 입력 문자열의 각 문자당 단 한 번의 상태 전이만 발생하므로 실행 속도가 매우 빠릅니다.

### **NFA vs DFA 판별 기준**

| 구분                | 결정적 유한 오토마타 (DFA)               | 비결정적 유한 오토마타 (NFA) |
| :------------------ | :--------------------------------------- | :--------------------------- |
| **$\epsilon$-전이** | 허용되지 않음                            | **허용됨**                   |
| **전이의 수**       | 상태 $s$와 입력 $a$에 대해 **오직 하나** | 여러 개 존재 가능            |
| **결정론적 동작**   | 입력에 따른 경로가 유일함                | 여러 경로 중 선택 가능       |

## 정규 표현식을 스캐너 코드로 변환하기

정규 표현식을 효율적인 스캐너로 만들기 위해 다음과 같은 논리적 단계를 거칩니다.

- **RE → NFA:** **톰슨의 구성(Thompson's construction)**을 사용하여 정규 표현식의 각 기호와 연산자를 NFA로 변환합니다.
- **NFA → DFA:** **부분집합 구성(Subset construction)**을 통해 비결정적인 NFA를 결정적인 DFA로 변환하여 시뮬레이션 가능하게 만듭니다.
- **DFA → Minimal DFA:** **Hopcroft 알고리즘(상태 최소화)**을 사용하여 DFA의 상태 수를 줄여 메모리 효율을 높입니다.
- **Minimal DFA → Code:** 최종적으로 전이 테이블(Transition Table)이나 코드를 생성하여 스캐너를 완성합니다.

---

### Thompson's Construction

정규 표현식의 구문 구조를 따라가며 인덕티브(Inductive) 방식으로 NFA를 빌드하는 방법입니다.

#### **기본 사례 (Inductive Base)**

- **공집합($\epsilon$):** 입력을 소비하지 않고 상태 $S_0$에서 $S_1$으로 이동하는 NFA를 생성합니다.
- **단일 기호($\underline{a}$):** 알파벳에 속한 기호 $a$를 입력받아 상태를 전이하는 기본 NFA를 생성합니다.

#### **인덕티브 단계 (Inductive Step)**

복합적인 정규 표현식을 결합할 때는 연산자 우선순위에 따라 $\epsilon$-전이(moves)를 사용하여 연결합니다.

1.  **선택 (Selection, $r | s$):** 새로운 시작 상태와 종료 상태를 만들고, $r$과 $s$의 NFA로 갈라지는 $\epsilon$ 경로를 추가합니다.
2.  **연결 (Concatenation, $rs$):** $r$의 종료 상태를 $s$의 시작 상태와 연결합니다. (교재에서는 두 가지 모델을 소개하며, 종료와 시작 상태를 하나로 합치거나 $\epsilon$으로 잇는 방식이 있습니다.)
3.  **반복 (Kleene Star, $r^*$):** $r$의 종료 상태에서 시작 상태로 돌아가는 $\epsilon$ 경로와, $r$을 완전히 건너뛰는 $\epsilon$ 경로를 추가하여 0회 이상의 반복을 구현합니다.

### Thompson's Construction의 특징

- **구문 중심(Syntax-driven):** 정규 표현식 r의 구조를 그대로 따라가며 기계적으로 생성할 수 있습니다.
- **별도 구성:** 동일한 기호 $a$가 정규 표현식 내에 여러 번 등장하더라도, 각 출현 위치마다 별도의 NFA를 생성하여 결합합니다.
- **복잡성:** 사람이 설계한 것보다 상태 수가 훨씬 많은 복잡한 오토마타가 생성될 수 있으나, 이 과정이 **자동화** 가능하다는 점이 가장 큰 장점입니다.
- **구현 모델의 차이:** Wikipedia 방식(종료 상태와 다음 시작 상태를 $\epsilon$으로 연결)과 일부 온라인 자료(상태를 직접 병합)의 표기법 차이가 있을 수 있음을 명시하고 있습니다.

---

### Subset Construction의 핵심 개념

NFA는 동일한 입력 심볼에 대해 여러 상태로의 전이가 가능하므로 최적의 경로를 "추측(Guessing)"해야 하는 문제가 발생합니다. 잘못된 추측은 유효한 문자열을 거부(Reject)하게 만들 수 있습니다.

- **병렬 전이 시뮬레이션:** NFA의 비결정론적 특성을 해결하기 위해, 특정 심볼을 읽었을 때 도달 가능한 모든 상태를 동시에 탐색합니다.
- **가상 상태(Virtual State) 도입:** NFA에서 한 번에 가존재할 수 있는 여러 상태의 집합을 DFA의 **하나의 가상 상태**로 정의합니다.
  - 예: 상태 $s_1$에서 'a'를 읽어 $s_1, s_2$에 도달 가능하다면, DFA에서는 $\{s_1, s_2\}$라는 새로운 단일 상태를 생성합니다.
- **전이 규칙:** 가상 상태 $\{s_1, s_2\}$에서 심볼 'b'를 읽었을 때의 전이는, 각 구성 요소 상태($s_1$ 또는 $s_2$)에서 'b'를 통해 갈 수 있는 모든 NFA 상태들의 집합으로 정의됩니다.

### 알고리즘의 주요 함수

변환 프로세스를 공식화하기 위해 두 가지 핵심 함수를 사용합니다.

- **$Move(S_i, a)$:** 상태 집합 $S_i$에 속한 모든 상태에서 입력 심볼 $a$를 통해 직접적으로 도달 가능한 NFA 상태들의 집합을 반환합니다.
- **$\epsilon\text{-closure}(S_i)$:** 상태 집합 $S_i$에서 입력 심볼 없이 $\epsilon$(empty transition)만을 따라 도달할 수 있는 모든 상태의 집합을 반환합니다.

### NFA-to-DFA 알고리즘 루틴

알고리즘은 전체 탐색이 완료될 때까지 반복되는 **고정점 계산(Fixed-point computation)** 방식을 따릅니다.

```
Dstates := {}; // DFA의 상태 집합 (초기화)
// NFA의 시작 상태 s0의 ε-closure를 계산하여 DFA의 시작 상태로 설정
T0 := ε-closure({s0});
add T0 as an unmarked state to Dstates;

while (there is an unmarked state T in Dstates) {
mark T; // 현재 처리 중임을 표시
for each input symbol a in Σ {
// 현재 상태 집합 T에서 a를 통해 갈 수 있는 상태들의 ε-closure 계산
U := ε-closure(Move(T, a));

        // 새로운 상태 집합 U가 기존 Dstates에 없으면 추가
        if (U is not in Dstates) {
            add U as an unmarked state to Dstates;
        }

        // DFA의 전이 함수 정의: δ[T, a] := U
        δ[T, a] := U;
    }

}
```

1.  **초기화:** NFA의 시작 상태 $s_0$의 $\epsilon\text{-closure}$를 구해 DFA의 시작 상태 $S_0$를 생성하고 `Dstates`에 추가합니다.
2.  **반복:** `Dstates` 내에 아직 처리되지 않은(unmarked) 상태 $T$가 있는 동안 다음을 수행합니다.
    - 각 입력 심볼 $a \in \Sigma$에 대해 $U = \epsilon\text{-closure}(Move(T, a))$를 계산합니다.
    - 새로운 상태 $U$가 `Dstates`에 없다면 추가합니다.
    - DFA의 전이 함수 $\delta[T, a] = U$를 기록합니다.
3.  **종료 조건:** 더 이상 새로운 가상 상태가 생성되지 않으면 루프를 종료합니다.
4.  **최종 상태 정의:** NFA의 수락 상태(Final state)를 하나라도 포함하고 있는 모든 가상 상태는 DFA의 수락 상태가 됩니다.

### 알고리즘의 특성

- **정지성(Termination):** DFA의 상태 집합은 NFA 상태 집합의 멱집합(Powerset) 내에 존재하므로 유한하며, `Dstates`는 단조 증가(Monotone)하므로 결국 수렴하여 종료됩니다.
- **정확성:** 이 과정은 NFA가 가질 수 있는 모든 가능한 구성(Configuration)을 체계적으로 구축하여 결정론적 동작을 보장합니다.

### 실행 예시: $a(b|c)^*$

정규 표현식 $a(b|c)^*$를 NFA에서 DFA로 변환하는 과정을 보여줍니다.

- **상태 압축 효과:** 예시에서는 Subset Construction을 거친 결과, DFA의 상태 수가 NFA보다 적게 생성될 수 있음을 보여줍니다.
- **결정론적 전이:** 결과물인 DFA는 모든 전이가 입력 심볼에 대해 단 하나의 상태로만 연결되며, 실제 스캐너 구현 시 효율적인 테이블 기반 조회가 가능해집니다.

## Table-driven 방식과 Direct-coded 방식의 구현 편의성 및 성능 비교

### 1. Table-driven Scanner (테이블 구동형 스캐너)

오토마톤(Automaton)을 하나의 거대한 상태 전이 테이블(Transition Table)로 인코딩하여 동작하는 방식입니다.

- **구현 특성:**
  - **자동화 용이성:** 정규 표현식으로부터 자동으로 생성하기에 매우 적합한 방식입니다.
  - **수동 구현의 어려움:** 사람이 직접 거대한 테이블과 전이 로직을 수동으로 코딩하는 것은 매우 어렵고 비효율적입니다.
- **성능 관련 제약:**
  - **비싼 룩업 비용:** 현재 상태와 입력 캐릭터를 기반으로 테이블의 특정 셀을 계산하고 접근하는 과정이 필요합니다.
  - **캐시 비친화적(Not cache-friendly):** 전이 테이블의 크기가 CPU의 캐시 메모리 크기를 초과할 경우, 메모리 액세스 속도 저하로 인해 성능이 떨어질 수 있습니다.

### 2. Direct-coded Scanner (직접 코드형 스캐너)

오토마톤의 상태 전이 로직을 프로그램 카운터(PC), 즉 실제 실행 코드로 직접 인코딩하는 방식입니다.

- **구현 특성:**
  - **코드 구조:** `if-else` 또는 `switch-case` 문을 사용하여 특정 문자를 읽었을 때 다음 코드 블록으로 실행 흐름을 제어합니다. (예: `if` 문자를 읽고 난 뒤 다음 문자가 `=`인지 확인하는 분기문 구조)
  - **범용성:** 자동화된 도구뿐만 아니라 수동으로 구현하는 것도 충분히 가능합니다.
- **성능 관련 이점:**
  - **테이블 룩업 제거:** 참조할 테이블이 없으므로 메모리 룩업 오버헤드가 발생하지 않습니다.
  - **분기 예측 활용:** `x86`과 같이 분기 예측(Branch Prediction) 성능이 좋은 현대적 아키텍처에서 효율적으로 동작합니다.
  - **속도 우위:** 일반적으로 범용 CPU 환경에서는 Table-driven 방식보다 더 빠른 성능을 보입니다.
- **단점:**
  - **복잡한 제어 흐름:** 상태가 많아질수록 제어 흐름(Control Flow)이 매우 복잡해질 수 있습니다.

#### 요약 비교 테이블

| 구분            | Table-driven               | Direct-coded                   |
| :-------------- | :------------------------- | :----------------------------- |
| **핵심 기제**   | 상태 전이 테이블 인코딩    | 프로그램 카운터(코드)에 인코딩 |
| **자동화**      | 매우 용이                  | 용이                           |
| **수동 구현**   | 매우 어려움                | 가능함                         |
| **메모리**      | 캐시 미스 발생 가능성 있음 | 테이블 필요 없음               |
| **일반적 성능** | 상대적으로 느림            | 상대적으로 빠름                |
